# 双轮速度闭环联调

当前默认启用电脑蓝牙调参模式，使用 VOFA/串口工具或临时脚本调试，协议见 [串口调试说明](../tools/SERIAL_DEBUG.md)。本页的固件内置自动试转步骤仅在 `BLUETOOTH_TUNE_ENABLE=0` 时生效，避免两个调试入口同时控制电机。

## 当前实现

`speed_control.c/.h` 负责左右轮独立 PID，以编码器 `counts/s` 为输入、千分比占空比为输出。用户已完成轮端标定，脚本可根据保存的标定参数换算 mm/s，固件内部仍使用 counts/s。当前采用固定最高速度方案，下一步实测找到不后仰且运行稳定的最大速度并固化上限，见 [交接文档](../HANDOFF.md)。主循环继续采集三路 ToF 和 MPU6050，暂未加入航向积分、直行纠偏、测距停车或迷宫任务。

上电完成 `Motor_Init()`、`Encoder_Init()` 后调用 `SpeedControl_Init()`，保持电机禁用。编码器每产生一份新采样，控制器计算一次 PID；重复轮询同一采样不重复积分。积分使用实际 `interval_ms`，输出和积分均限幅，饱和时冻结继续推向饱和的积分变化。微分作用于测量值，避免改变目标时产生微分冲击。零目标为滑行停车，超速时也只撤销驱动，不反向制动。

控制器启用期间独占 `Motor_Enable/Disable/SetDuty`，上层只能通过速度控制接口发运动命令。`Motor_Process()` 仍由主循环持续调用，执行原有启动等待和换向空档。

## 上电与试转

1. 默认 `main.c` 中 `MOTOR_DEBUG_SPEED_ENABLE=0`，上电只采集和发送调试帧，不转动电机。架空小车，手动向前转动两轮，确认帧中的左右实测速度均为正；若方向错误，调整 `encoder.h` 对应的 `ENCODER_*_SIGN`。
2. `main.c` 的 `speed_config` 为左右轮独立参数，当前左轮 `Kp=0.8、Ki=1.5、Kd=0`，右轮 `Kp=0.6、Ki=1.5、Kd=0`，目标限幅 ±2100 counts/s，输出限幅 ±700（70%）。这些是落地暂定参数，后仰问题尚未解决，不应直接提高速度上限。
3. 若使用固件内置试转，保持架空，将 `BLUETOOTH_TUNE_ENABLE` 改为 `0`、`MOTOR_DEBUG_SPEED_ENABLE` 改为 `1`，编译烧录。获得首份有效编码器反馈后，两轮按 `MOTOR_DEBUG_SPEED_COUNTS_PER_S` 目标试转，经过 `MOTOR_DEBUG_SPEED_DURATION_MS` 后停机，同一次上电不重复启动。具体目标和时长以当前 `main.c` 为准。调试器暂停 CPU 时软件保护也会暂停，运动期间不要使用断点。
4. 先令 Ki、Kd 为零，分别调两轮 Kp，确认实际速度方向正确且随目标变化，再逐步增加 Ki 消除静差。观察目标、实测和请求占空比；零反馈会按速度误差继续调节至限幅，本版没有堵转检测或电流保护。禁止依靠反馈超时保护识别卡轮或编码器断线后持续零计数。
5. 架空调试稳定后再低速落地验证负载下的速度跟随和停车距离，完成后关闭自动试转开关。当前速度试转不依赖 ToF/MPU 状态，也不具备自动避障，必须保留足够测试空间。

## 上层接口

仅在主循环调用，禁止在中断中执行。新任务先等待有效采样，再调用：

```c
/* 只有 HAL_OK 才表示已使能，HAL_BUSY 表示还没有新鲜有效反馈。 */
status = SpeedControl_Enable();
if (status == HAL_OK)
{
  /* 左右轮可独立给定目标，单位 counts/s。 */
  status = SpeedControl_SetTarget(300.0f, 300.0f);
}
/* 结束任务时撤销输出并清除积分，之后必须重新显式使能。 */
SpeedControl_Stop();
```

`SetTarget(0, 0)` 立即撤销双轮输出及积分，保留 RUNNING；`Stop()` 同时禁用电机并回到 IDLE。单轮目标为零只清除该轮控制量，另一轮继续控制。换向时先撤销该轮输出和积分，新采样到达后重新计算，并继续经过底层电机换向保护。

## 状态与故障

`car_speed` 保存公开状态，`speed_control_status` 为最近轮询的 HAL 结果。待机或无新采样时 `HAL_BUSY` 属于正常情况。状态值：0 待机、1 运行、2 故障。故障值：0 无、1 编码器反馈、2 电机命令失败、3 非法目标（NaN、无穷大等）。

反馈无效、时间间隔或反馈年龄达到 50 ms，立即清零命令并禁用电机；故障锁存，不能自动恢复。先排除故障，再调用 `SpeedControl_Stop()` 清除锁存，等待有效反馈后重新显式使能。新鲜时间戳不能掩盖跨度过大的采样间隔。

主循环在耗时 I2C 访问前后检查反馈年龄，且 ToF 返回后先检查旧反馈，再更新编码器。I2C 仍是有界阻塞访问，50 ms 为检查阈值，**不是硬件保证的最迟停机时间**：停机操作必须等主循环恢复执行。本版不提供独立硬件看门狗停机；故障注入时应实际测量最长阻塞和撤销输出延迟。

## 蓝牙帧

默认 `SPEED_DEBUG_TELEMETRY_ENABLE=1`，每 200 ms 发送一帧：

```text
speed:状态,故障,左目标,右目标,左实测,右实测,左请求占空比,右请求占空比
```

速度取整为 counts/s，占空比为千分比。实测字段来自最新编码器快照，待机时也可观察手转方向；字段不包含反馈有效性，陈旧数据应结合 ST-Link 的 `car_encoder.sample_valid/timestamp_ms` 判断。请求占空比并不代表启动等待、换向空档中的实际 PWM。USART2 仍为 9600 波特率，忙时丢弃当前帧，不排队等待；设置 `SPEED_DEBUG_TELEMETRY_ENABLE=0` 可关闭输出。三路 ToF 原有测试帧未恢复。

## 验证

在 `software/car/` 运行：

```powershell
./tests/run_speed_control.ps1
```

需要 PATH 中的 MinGW gcc。测试链接真实编码器、电机和速度控制代码，仅模拟 HAL 及硬件寄存器，覆盖：上电禁用、首样本门控、重复采样、实际时间积分、目标及输出限幅、饱和退出、零速清积分、单轮换向、超速滑行、反馈超时/长间隔/半范围歧义、故障锁存与恢复、非法目标、电机接口失败、节拍回绕及测量微分。

Keil 工程已加入 `speed_control.c`。主机测试和目标编译只能验证软件路径，实物调参、方向确认、负载测试和故障停车仍需完成。
