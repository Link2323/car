# 编码器标定与速度换算

用户已完成轮端标定，现有结果保存在 `wheel_calibration.json`，应直接保留使用。只有更换车轮、传动或需要复核测量时才重新标定。自制电脑界面已删除，以下流程通过串口工具或临时脚本完成，命令格式见 [串口调试说明](SERIAL_DEBUG.md)。

## 当前参数

| 参数 | 左轮 | 右轮 |
|---|---:|---:|
| 每圈计数 counts/rev | 2770.2 | 2772.0 |
| 周长 mm | 138.230077 | 138.230077 |

```text
每计数毫米 = 周长(mm) / 每圈计数(counts/rev)
轮端速度(mm/s) = 编码器计数率(counts/s) × 每计数毫米
目标计数率(counts/s) = 目标轮端速度(mm/s) / 每计数毫米
累计轮程(mm) = 有符号累计计数(counts) × 每计数毫米
```

100 mm/s 分别对应约 2004/2005 counts/s，按每轮参数单独换算并取整。固件内部仍使用 counts/s，标定 JSON 不会自动加载到 MCU；临时脚本需要自行读取并换算。未知周长可保留为 `null`，参数不完整、非有限正数时不进行物理单位换算。换算后的目标必须受已经确认的速度上限约束。

轮端速度和累计轮程是编码器估计，离地或打滑时不等于车身实际速度/位移。累计从上电或最近一次标定清零开始，倒转会减小，不是每次试转自动清零的距离。

## 必要时重新标定

1. 确认实际串口，使用 9600/8N1；更换电脑后重新识别端口，不沿用历史 COM 编号。确认固件支持标定命令。
2. 架空并等待两轮停止，在车轮与车架标记起始位置。发送 `tune:id,6`，等待匹配的 `cal:` 回执，确认标定模式为 1、采样和累计有效、计数接近零。进入标定会撤销输出并锁住启动入口；清零仅重设软件计数基线。
3. 两轮分别朝前进方向完整手转 5～10 圈，记录各自准确圈数。可以先左后右，两轮测完前不要再次清零。
4. 双轮静止后发送 `tune:新id,7`，等待新的有效 `cal:` 回执。每轮每圈计数为该轮累计计数除以实际圈数。累计应为正，采样及累计有效位均应为 1；数据陈旧、方向错误或累计无效时不采纳，排查后重新标定。
5. 每圈计数已经包含传动比、编码器线数及实际计数模式，不要再次乘减速比或四倍频。测量轮子正常载重下无滑动滚动多圈的距离，除以圈数得到有效周长；也可用 π×轮径作为初步估计，再用实测修正。
6. 将确认后的每圈计数和周长写入 `wheel_calibration.json`，保持原有左右轮字段结构。发送 `tune:新id,8` 退出标定，确认模式为 0；退出后仍禁用电机，不自动启动。

普通停止、断开和重新连接不会解除标定锁；只有退出标定命令或 MCU 复位解除。MCU 复位后电机同样默认禁用。

## 回执及有效性

```text
cal:id,标定模式,左累计,右累计,采样有效,累计有效,采样时间戳ms
enc:标定模式,左累计,右累计,采样有效,累计有效,采样时间戳ms
```

模式及有效位为 0/1，累计为有符号 64 位，时间戳为 MCU 无符号 32 位毫秒节拍。正常累计快照约 1 Hz，标定中约 5 Hz；速度取自约 5 Hz 的 `speed:` 帧。脚本应检查数据新鲜度及有效标志，不使用过期计数计算新标定，不将无效数据换算为物理量。

真实固件协议的主机回归保留了进入标定先停机、模式锁、重复命令不重复清零、64 位计数、累计无效、退出不自动启动等验证。最新实物进度及最大速度确认任务见 [交接文档](../HANDOFF.md)。
